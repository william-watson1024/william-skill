# 初始化项目目录与开发环境

生成可以继续开发的目录和工具环境，而非可运行应用。不要将当前宿主项目的业务、框架或依赖当成新项目默认值。

## 收集当前项目的信息

从当前请求和对话中提取以下信息，只引导用户回答缺失项，不跨项目记忆答案：

- 项目名称：区分展示名、目录名、包名；按所选工具的命名限制规范化技术名称，不擅自改变展示名。
- 目标目录：给出最终绝对路径，明确它与当前工作目录的关系，不默认初始化 skill 所在仓库。
- 前端技术栈：框架、语言、构建工具与包管理器。
- 后端技术栈：语言、框架与依赖管理器。
- 项目目的：为谁解决什么问题。
- 核心业务需求：主要功能和本次不做的内容，用来解释模块边界，不据此实现业务。

优先用一次简洁提问收集缺失信息。用户不熟悉技术时，解释选择影响并推荐适合用途的组合；用户授权代选后再采用推荐方案，不要求其掌握工具细节。操作系统、现有工具和已安装版本自行检查，不让用户重复提供可读取的事实。

信息齐备后简要说明目标路径、技术栈、目录及环境配置，直接在已有初始化授权范围内执行，不另设一轮固定审批。

## 写入前的硬性条件

在任何 mkdir、git init、环境创建或依赖安装之前检查目标：

1. 目标不存在，或是完全空的真实目录，才能初始化。
2. 非空即拒绝，隐藏文件也算；只有 `.git`、`.gitkeep`、`.codex` 或 `.DS_Store` 也不例外。不要豁免“看起来无害”的已有文件，不做补齐、覆盖或清理。
3. 符号链接、普通文件及其他非目录目标拒绝处理，避免误写到实际指向的其他目录。
4. 拒绝时不修改目标，不执行 git init，也不自动选择新路径；说明冲突并请用户提供新的空目录。
5. 真正写入前再次检查，防止讨论期间目标已有内容。检查输出不展开配置文件、密钥等内容。

区分“编写或安装本 skill”与“执行本 skill 初始化项目”：此硬性条件针对后者，不能以 skill 本身在已有仓库为由修改该仓库的应用文件。

## 生成范围

必需的根级结构如下；示例目录名是约定，不代表固定技术栈：

```text
<project>/
├── frontend/
│   ├── src/
│   ├── public/assets/        # 框架使用此资源惯例时生成
│   ├── .env
│   ├── .env.example
│   └── <依赖清单、真实锁文件及必要工具配置>
├── backend/
│   ├── <符合所选语言的源码目录>
│   ├── tests/
│   ├── .env
│   ├── .env.example
│   └── <依赖清单、真实锁文件及必要工具配置>
├── assets/                  # 原始素材、设计参考；不与运行时资源重复存放
├── docs/
│   ├── 100-project/110-overview.md
│   ├── 200-architecture/210-system-design.md
│   └── 300-development/310-local-development.md
├── AGENTS.md
├── .gitignore
├── Makefile
└── README.md
```

- 为必要的空目录放置 `.gitkeep`，不要放进已有实际文件的目录；不生成图片或其他素材。
- 结合核心业务在架构文档说明未来功能边界，只创建有明确当前用途的目录，不批量生成未来业务模块、抽象类或空代码文件。
- 不生成页面、应用入口、API、健康检查、业务逻辑、测试代码或占位应用。不调用会自动生成这些内容的框架脚手架。
- 不默认引入数据库、认证、Docker、CI、RAG、Agent 框架或外部服务；用户明确选定的依赖除外。

## 配好环境，但不宣称应用可启动

查看所选技术的官方约定及兼容版本，使用相应包管理器生成真实依赖锁文件，不手工编造锁文件或固定沿用其他项目的版本。

- Python + uv：创建 `pyproject.toml`、明确 Python 版本要求和合适的 `.python-version`，采用 src-layout；由 uv 创建 backend 内 `.venv`、安装选定依赖并生成 `uv.lock`。尚无可安装源码包时采用非打包项目配置，不声明不存在的包或入口。
- Node 前端：生成符合框架选择的 `package.json`、工具版本要求及适用的工具配置，使用选定包管理器安装依赖，只保留该管理器的锁文件。不要定义引用不存在入口或配置的 npm scripts。
- 其他技术栈：遵循对应语言的依赖清单、锁文件和项目内环境惯例，不强套 Python 或 Node 目录结构。
- 工具本身使用持久的用户级或系统级安装，项目依赖使用项目内隔离环境；不用临时目录作为长期运行依赖，不提交工具二进制。
- 缺少工具或安装被网络/权限阻塞时，说明缺项和适用安装方式；未获授权不修改全局环境。保留已生成文件并如实说明环境未完成，不声称成功、不自动删除重做。后续再次初始化仍遵守非空拒绝规则，需要用户明确授权单独恢复未完成步骤。

### 环境变量与忽略规则

- 前后端分别生成 `.env` 和带中文注释的 `.env.example`，默认不创建根级 `.env`。
- 示例不含真实密钥；本地 `.env` 使用可公开的本地开发默认值或留空的待填项。只列本项目确实需要的配置，不添加与技术栈无关的模型或数据库变量。
- 前后端 API 地址、端口与计划的本地 CORS 来源一致；如计划支持 localhost 和 127.0.0.1，配置示例说明二者。没有应用代码时说明这些值尚未被应用读取，不暗示配置加载或 CORS 中间件已实现。
- 不能将秘密放入 VITE_、NEXT_PUBLIC_ 等会暴露给浏览器的变量。
- `.gitignore` 按环境配置、后端、前端、测试/覆盖率、操作系统分类，附中文注释；规则适配所选工具。忽略 `.env`、本地环境、依赖和构建缓存，显式保留 `.env.example`，保留真实锁文件。

## 文档与 AGENTS.md

`README.md` 只包含项目名称、环境、Makefile 说明、前后端启动五部分。名称作为文档标题，后四项作为章节；不额外加入架构、路线图或测试章节。启动部分注明当前没有应用入口，待后续实现，不填写虚构的启动命令。测试、验证及架构信息放入 docs。

docs 使用软件项目适用的杜威十进制层级编号，而非图书学分类：

- 100-project：项目目的、用户、业务需求及非目标；110-overview.md 记录本次真实输入。
- 200-architecture：前后端目录、职责和依赖边界；210-system-design.md 解释选择及未来扩展位置。
- 300-development：环境、安装、验证和后续开发说明；310-local-development.md 记录实际可执行命令及限制。
- 新类别使用未占用的百位编号，类别内按十位递增，如 310、320；目录和文件采用“编号-英文短名”，同一层级不重号。只为实际内容新增文档，不预建空分类。

生成大小写精确的根目录 `AGENTS.md`，内容包括：项目目的与技术栈、源码与素材边界、规范驱动开发和测试驱动开发、上述 docs 分类/编号/命名与新增文档规则、依赖和秘密处理约定、以实际存在的 Makefile 目标为命令入口。不要复制整套 skill 指令，也不要写入个人机器绝对路径。

## Makefile

按当前技术栈提供真正能执行的环境命令，至少包含 help、env、install、check-env：

- 默认 help，命令旁附中文说明，声明伪目标。
- env 仅从示例补齐缺失的 .env，不覆盖已有配置。
- install 根据锁文件恢复前后端依赖，环境文件准备作为明确前置依赖；生成锁文件是首次初始化过程，不在日常安装中静默升级。
- check-env 检查所需工具和版本，不伪装成业务测试或服务健康检查。
- 不要求 dev、backend、frontend、test、build 存在。没有对应实现就省略目标，在 docs 记录后续需要增加哪些入口，不用 echo 假装成功。
- 不把个人绝对路径、临时工具路径或真实密钥写入命令，检查所选系统是否支持 Makefile 用到的 shell 功能。

## Git 与 Codex 本地文件

在通过空目录检查并开始初始化后，在该目标内执行 git init；不 git add、不提交、不设置远程仓库、不修改用户级 Git 配置。

在该新仓库 `.git/info/exclude` 追加以下根目录规则，保留已有内容且不重复追加：

```gitignore
# Codex 本地配置与项目指令
/AGENTS.md
/.codex/
/.agents/
```

`.codex/` 留给 Codex 本地配置，不为排除规则预建空配置。需要项目级 skill 时，Codex 当前官方发现目录为 `.agents/skills/`；若用户选择将实体放在 `.codex/skills/`，可用 `.agents/skills/<name>` 符号链接指向实体。不创建虚假的 Codex 配置，不复制本 skill 到每个新项目，除非用户另有要求。

## 验收与交付

- 确认目录、配置、依赖清单与真实锁文件存在；验证安装成功和项目内环境位置，不运行不存在的应用、测试或构建入口。
- 验证 make help、make check-env 和可用环境命令；执行 env 前后确认已有 .env 不变。
- 验证 .env、AGENTS.md、.codex 和 .agents 被 Git 忽略，.env.example 和锁文件未被忽略，Git 仓库确实建立。
- 只报告实际执行的检查。交付目标路径、选定技术栈、可用的 make 命令，以及缺失工具/网络导致的未完成项；明确这是目录和环境骨架，没有应用代码。

本 skill 在当前项目的实体位于 `.codex/skills/init-project/`，通过 `.agents/skills/init-project` 链接发现。官方发现约定参考：https://learn.chatgpt.com/docs/build-skills 。
